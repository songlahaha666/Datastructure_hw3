1. 解題說明

本程式的目標是設計一個圖形資料結構 Graph，並使用鄰接串列來儲存圖中各個頂點之間的連結關係。
程式提供了圖的基本操作，包含判斷圖是否為空、查詢頂點數與邊數、計算某個頂點的度數、檢查邊是否存在、插入頂點、插入邊、刪除頂點與刪除邊等功能。
此外，也另外設計了輸出函式，可以將圖以鄰接串列與鄰接矩陣兩種方式顯示，方便觀察圖的結構變化。

這個程式主要是用來練習圖形結構的基本操作，並理解鄰接串列在無向圖中的實作方式。透過實際建立圖形、加入邊、刪除邊與刪除頂點，可以驗證各項功能是否正確運作。

2. 演算法設計與實作

程式採用鄰接串列來表示圖，每個頂點都對應一個 vector，用來存放與它相連的所有鄰接點。
當新增一條無向邊時，程式會同時把兩個頂點彼此加入對方的鄰接串列中。
查詢邊是否存在時，則直接在其中一個頂點的鄰接串列內搜尋另一個頂點。
刪除邊時，會從兩端頂點的鄰接串列中同時移除對方，並更新邊數。
刪除頂點時，則需要重建整個鄰接串列陣列，並將編號大於被刪除頂點的鄰點全部減一，確保頂點編號連續。

另外，程式中的 showArraylist() 可以將每個頂點的鄰接點完整列出；showMartix() 則會根據鄰接串列重新判斷每一對頂點之間是否有邊，輸出成矩陣形式，方便檢查圖的連結狀況。

3. 效能分析

圖的基本查詢與更新操作在鄰接串列結構下具有不同的時間複雜度。

輸入邊與查詢邊是否存在，平均情況下需要搜尋鄰接串列，因此時間複雜度約為 O(deg(v))。
查詢某個頂點的度數則可以直接取得鄰接串列長度，因此為 O(1)。
新增邊的時間複雜度為 O(1)。
刪除邊需要在兩個鄰接串列中搜尋並移除資料，因此約為 O(deg(u) + deg(v))。
刪除頂點時需要重建整個圖的鄰接串列並重新調整編號，因此時間複雜度較高，約為 O(n + e)。
輸出鄰接串列為 O(n + e)，輸出鄰接矩陣則為 O(n²)。

空間方面，鄰接串列只會儲存實際存在的邊，因此比鄰接矩陣更節省空間，整體空間複雜度約為 O(n + e)。

4. 測試

程式在 main() 中先建立一個包含 10 個頂點的圖，接著依序加入多條邊，形成一個無向圖。
之後會輸出圖是否為空、頂點數、邊數、某個頂點的度數，以及某條邊是否存在。
再透過 showArraylist() 與 showMartix() 顯示圖的結構，最後測試刪除邊與刪除頂點後，圖的資料是否正確更新。

從測試結果可以看出，加入邊後圖的鄰接關係正確建立，刪除邊與刪除頂點後，頂點數與邊數也會同步更新，表示程式功能符合預期。

5. 心得討論

這次的程式讓我更熟悉圖形資料結構的實作方式，特別是鄰接串列在無向圖中的應用。
一開始只要處理新增與查詢邊還算直觀，但在刪除頂點時，因為涉及整個圖的重新編號與資料重建，所以比其他操作更容易出錯，也更能體會資料結構設計時的細節。

透過這個程式，我也更清楚理解到不同圖形表示法的差異。鄰接串列雖然在輸出矩陣時需要額外判斷，但在空間使用上比鄰接矩陣更有效率，尤其適合邊數不多的圖。
整體來說，這次實作不只是練習 C++ 語法，也讓我對圖的操作流程與資料維護方式有更完整的理解。
